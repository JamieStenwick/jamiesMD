Custom LTO Helper#

cuFFT Device API through Example#

Here we cover code snippets from 10_cufft_device_api_example/cufft_device_api_example, a cuFFTDx example similar to the one detailed in the Use Case I: Offline Kernel Generation section, which adds LTO support to an existing non-LTO project. The source and build changes required to add LTO support to cufft_device_api_example are identical to the changes covered in 09_introduction_lto_example/introduction_lto_example. This example demonstrates how to build an example-specific helper for LTO database creation using the cuFFT Device API directly, as an alternative to using the LTO Helper.

Building the LTO database through the cuFFT Device API involves the following:

  1. For each FFT operation that should be included in the database, call the helper function Frontend to Backend Traits Conversion to map the traits of a FFT operation to the effective backend traits.

    #include "cufftdx/utils.hpp"

auto backend_traits = cufftdx::experimental::utils::frontend_to_backend(
   cufftdx::utils::algorithm::ct,
   cufftdx::utils::execution_type::block,
   128 /* fft_size */,
   cufftdx::fft_type::c2c,
   cufftdx::fft_direction::forward,
   750 /* sm */,
   cufftdx::real_mode::normal,
   8 /* elements_per_thread */,
   0 /* block_dim_x */,
   cufftdx::experimental::code_type::ltoir
);

  2. Create description handles for each mapped backend traits. cufftDescriptionSetTraitInt64 is used to set the traits for a given description handle.

    cufftDescriptionHandle desc_handle;
cufftDescriptionCreate(&desc_handle);
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_SIZE,
   static_cast<long long int>(backend_traits.size));
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_TYPE,
   static_cast<long long int>(backend_traits.type));
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_DIRECTION,
   static_cast<long long int>(backend_traits.direction));
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_SM,
   static_cast<long long int>(backend_traits.sm));
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_PRECISION,
   static_cast<long long int>(backend_traits.precision));
cufftDescriptionSetTraitInt64(desc_handle, CUFFT_DESC_TRAIT_ELEMENTS_PER_THREAD,
   static_cast<long long int>(backend_traits.elements_per_thread));

  3. Create a device handle from the description handle(s).

    cufftDeviceHandle device_handle;
cufftDeviceCreate(&device_handle, 1, &desc_handle);

    Hint

    cuFFT exposes an API, cufftDeviceIsSupported, to check whether a given description handle provided to the device handle is valid, supported, or unsupported:

    cufftDeviceIsSupported(device_handle, desc_handle);

  1. Obtain the database header file from the device handle and write it to disk. The header file contains information that informs cuFFTDx which FFT descriptions have LTO support.

    size_t database_str_size = 0;
cufftDeviceGetDatabaseStrSize(device_handle, &database_str_size);
char* database_str = (char*)malloc(database_str_size * sizeof(char));
cufftDeviceGetDatabaseStr(device_handle, database_str_size, database_str);

// Write database_str to disk as "lto_database.hpp.inc" and free all memory
// associated with database_str

  2. Obtain the database fatbin(s) and ltoir(s) from the device handle and write them to disk. The fatbin(s) and ltoir(s), when combined with the cuFFTDx library, can be used to build the device functions that compute FFTs described by the description handle(s).

    size_t num_codes = 0;
cufftDeviceGetNumLTOIRs(device_handle, &num_codes);
size_t* code_sizes = (size_t*)malloc(num_codes * sizeof(size_t));
cufftDeviceGetLTOIRSizes(device_handle, num_codes, code_sizes);

cufftDeviceCodeType* code_types =
   (cufftDeviceCodeType*)malloc(num_codes * sizeof(cufftDeviceCodeType));
char** code_ptrs = (char**)malloc(num_codes * sizeof(char*));
for (size_t n = 0; n < num_codes; ++n) {
   code_ptrs[n] = (char*)malloc(code_sizes[n] * sizeof(char));
}

cufftDeviceGetLTOIRs(device_handle, num_codes, code_ptrs, code_types);

// Write code_ptrs[n] to disk as database_N.fatbin/ltoir and free all memory
// associated with code_ptrs/code_types

  3. Free the device handle.

    cufftDeviceDestroy(device_handle);

  4. Compile and run the database creation executable to produce and write the LTO database to disk.

    g++ -I<cufft_include_path> \
    -L<cufft_lib_path> \
    -I<cuda_include_path> \
    cufft_device_api_lto_helper.cpp -o cufft_device_api_lto_helper

    Once a database has been created, it can be included into and linked with an cuFFTDx LTO project using the steps detailed in Use Case I: Offline Kernel Generation.

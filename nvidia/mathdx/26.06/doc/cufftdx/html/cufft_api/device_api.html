cuFFT Device API Reference#

Warning

The API described in this section is experimental and is subject to change at any time. To acknowledge this notice, define CUFFT_ENABLE_EXPERIMENTAL_API before including cufft_device.h. Otherwise, the compiler will issue an error.

This section describes the extension to the cuFFT API included in the cuFFT library shipped as part of the CUDA Toolkit. It contains a collection of host functions that can be used to query or generate device function code along with the database metadata (a C++ header file) that can be used together with the cuFFTDx library.

Note

All functions discussed in this section are defined in the cufft/include/cufft_device.h header file.

Version Information#

cufftDeviceGetVersion#

cufftResult cufftDeviceGetVersion(int *version)#

Returns the version of the device code output by the cuFFT library, i.e., CUFFT_DEVICE_VERSION defined in cufft_device.h. Note that this is a separate versioning from the version of the cuFFT library itself.

Parameters:

  • version[Out] – Pointer to store the version number.

Return values:

  • CUFFT_SUCCESS – Version number was successfully retrieved.

  • CUFFT_INVALID_VALUE – The version pointer is NULL.

Description Management#

The set of functions used to specify which FFT implementations should be included in the database.

cufftDescriptionCreate#

cufftResult cufftDescriptionCreate(
cufftDescriptionHandle *desc_handle,
)#

Creates a new FFT description handle in memory owned and provided by the user.

Parameters:

  • desc_handle[In] – Pointer to a cufftDescriptionHandle object.

  • desc_handle[Out] – Contains a cufftDescriptionHandle handle value.

Return values:

  • CUFFT_SUCCESS – Description handle was successfully created.

  • CUFFT_INVALID_VALUE – The handle pointer is NULL.

  • CUFFT_INTERNAL_ERROR – The internal handle factory reaches its maximum capacity.

cufftDescriptionTrait#

Traits that can be set or queried for a FFT description (cufftDescriptionHandle). These traits correspond to the effective backend traits, as opposed to the frontend traits that can be set or queried for a FFT operator. To retrieve the backend traits associated with an FFT operator, use the helper function Frontend to Backend Traits Conversion.

typedef enum cufftDescriptionTrait_t {
   CUFFT_DESC_TRAIT_SIZE,               // Value: unsigned int
   CUFFT_DESC_TRAIT_DIRECTION,          // Value:
       // CUFFT_DESC_DIRECTION_<UNSET/FORWARD/INVERSE>
   CUFFT_DESC_TRAIT_PRECISION,          // Value:
       // CUFFT_DESC_<SINGLE/DOUBLE>
   CUFFT_DESC_TRAIT_TYPE,               // Value:
       // CUFFT_DESC_<C2C/C2R/R2C>
   CUFFT_DESC_TRAIT_SM,                 // Value: unsigned int
       // (e.g., 750, 800, 900)
   CUFFT_DESC_TRAIT_ELEMENTS_PER_THREAD // Value: unsigned int
} cufftDescriptionTrait;

cufftDescriptionSetTraitInt64#

cufftResult cufftDescriptionSetTraitInt64(
cufftDescriptionHandle desc_handle,
cufftDescriptionTrait trait,
const long long int value,
)#

Sets a trait value for a FFT description.

Parameters:

  • desc_handle[In] – cufftDescriptionHandle returned by cufftDescriptionCreate.

  • trait[In] – The trait identifier, of type cufftDescriptionTrait, to set.

  • value[In] – The value to set for the trait. See comments in cufftDescriptionTrait for valid values.

Return values:

  • CUFFT_SUCCESS – Trait was successfully set.

  • CUFFT_INVALID_VALUE – Invalid handle or trait.

cufftDescriptionGetTraitInt64#

cufftResult cufftDescriptionGetTraitInt64(
cufftDescriptionHandle desc_handle,
cufftDescriptionTrait trait,
long long int *value,
)#

Gets a trait value from an FFT description.

Parameters:

  • desc_handle[In] – cufftDescriptionHandle returned by cufftDescriptionCreate.

  • trait[In] – The trait identifier, of type cufftDescriptionTrait, to query.

  • value[Out] – Pointer to store the trait value.

Return values:

  • CUFFT_SUCCESS – Trait value was successfully retrieved.

  • CUFFT_INVALID_VALUE – Invalid handle or trait.

Device Management#

The set of functions that establish and manage mappings between FFT descriptions and their corresponding device functions and building blocks.

cufftDeviceCreate#

cufftResult cufftDeviceCreate(
cufftDeviceHandle *handle,
size_t desc_count,
cufftDescriptionHandle *desc_handles,
)#

Creates a new device handle with the specified FFT descriptions. For each FFT description provided, cuFFT will search for device functions with matching traits as well as the building blocks needed to generate the device functions.

Parameters:

  • handle[In] – Pointer to a cufftDeviceHandle object.

  • handle[Out] – Contains a cufftDeviceHandle handle value.

  • desc_count[In] – Number of descriptions.

  • desc_handles[In] – Pointer to an array of description handles with length desc_count.

Return values:

  • CUFFT_SUCCESS – Device handle was successfully created.

  • CUFFT_INVALID_VALUE –

    • The handle pointer or the pointer to the description handles pointer is NULL.

    • Any of the description handles used in the array is invalid.

  • CUFFT_INTERNAL_ERROR – The internal handle factory reaches its maximum capacity.

Note

We do not return an error if there is no matching device function or if the combinations of the traits values is invalid for the given description handles. This allows users to create a chunk of descriptions at once, and filter out the unsupported ones later in a separate step.

One could use cufftDeviceIsSupported defined below to check whether a description is valid, supported, or unsupported.

cufftDeviceIsSupported#

cufftResult cufftDeviceIsSupported(
cufftDeviceHandle handle,
cufftDescriptionHandle desc_handle,
bool *is_supported,
)#

Checks whether a description associated with the device handle is valid and supported. When the descriotion is valid, is_supported can be used to check if the description is supported.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • desc_handle[In] – cufftDescriptionHandle returned by cufftDescriptionCreate.

  • is_supported[Out] – Pointer to store the result.

Return values:

  • CUFFT_SUCCESS – Description is valid.

  • CUFFT_INVALID_VALUE –

    • Device handle handle or description handle desc_handle is invalid.

    • is_supported pointer is NULL.

    • The traits of the description are invalid, e.g. CUFFT_DESC_TRAIT_SIZE or CUFFT_DESC_TRAIT_SM is not set.

cufftDeviceDestroy#

cufftResult cufftDeviceDestroy(cufftDeviceHandle handle)#

Destroys a device handle and frees associated resources.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

Return values:

  • CUFFT_SUCCESS – Device handle was successfully destroyed.

  • CUFFT_INVALID_VALUE – Invalid handle.

Device Function Management#

The set of functions for retrieving device functions and device function traits.

cufftDeviceGetNumDeviceFunctions#

cufftResult cufftDeviceGetNumDeviceFunctions(
cufftDeviceHandle handle,
cufftDescriptionHandle desc_handle,
size_t *func_count,
)#

Gets the number of device functions that match a given description from the associated device handle. If the description is unsupported, i.e. no matched device function is found, or the traits of the description are invalid, 0 is returned.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • desc_handle[In] – cufftDescriptionHandle returned by cufftDescriptionCreate.

  • func_count[Out] – Pointer to store the number of functions.

Return values:

  • CUFFT_SUCCESS – Function count was successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle or desc_handle.

    • func_count pointer is NULL.

cufftDeviceGetDeviceFunctions#

cufftResult cufftDeviceGetDeviceFunctions(
cufftDeviceHandle handle,
cufftDescriptionHandle desc_handle,
size_t func_count,
cufftDeviceFunctionHandle *func_handles,
)#

Retrieves an array of device function handles that matches a given description associated with the device handle.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • desc_handle[In] – cufftDescriptionHandle returned by cufftDescriptionCreate.

  • func_count[In] – Number of function handles to retrieve. Value returned by cufftDeviceGetNumDeviceFunctions.

  • func_handles[Out] – Array to store the function handles.

Return values:

  • CUFFT_SUCCESS – Function handles were successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle or desc_handle.

    • func_handles pointer is NULL.

    • func_count is not equal to the number of functions returned by cufftDeviceGetNumDeviceFunctions.

cufftDeviceFunctionTrait#

Traits that can be queried for a device function (cufftDeviceFunctionHandle).

typedef enum cufftDeviceFunctionTrait_t {
    CUFFT_DEVICE_FUNC_TRAIT_ELEMENTS_PER_THREAD,
        // Elements per thread
    CUFFT_DEVICE_FUNC_TRAIT_STORAGE_SIZE,
        // Storage elements per thread
    CUFFT_DEVICE_FUNC_TRAIT_SHARED_MEMORY_PER_FFT,
        // Shared memory per FFT
    CUFFT_DEVICE_FUNC_TRAIT_THREADS_PER_FFT,
        // Threads per FFT
    CUFFT_DEVICE_FUNC_TRAIT_SUGGESTED_FFTS_PER_BLOCK,
        // Suggested number of FFTs processed per block
} cufftDeviceFunctionTrait;

cufftDeviceGetDeviceFunctionTraitInt64#

cufftResult cufftDeviceGetDeviceFunctionTraitInt64(
cufftDeviceHandle handle,
cufftDeviceFunctionHandle func_handle,
cufftDeviceFunctionTrait trait,
long long int *value,
)#

Gets a trait value from a device function.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • func_handle[In] – cufftDeviceFunctionHandle returned by cufftDeviceGetDeviceFunctions.

  • trait[In] – The trait identifier, of type cufftDeviceFunctionTrait, to query.

  • value[Out] – Pointer to store the trait value.

Return values:

  • CUFFT_SUCCESS – Trait value was successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle, func_handle or trait.

    • value pointer is NULL.

Database and Code Management#

The set of functions for retrieving:

  • LTOIRs that can be used to

    • Build all the device functions associated with the device handle (cufftDeviceHandle).

    • Build a specific device function when a function handle (cufftDeviceFunctionHandle) is provided.

  • Database metadata (a C++ header file).

These components, when used in combination with the cuFFTDx library, can be used to build kernels that compute the specified FFTs using LTO.

cufftDeviceGetDatabaseStrSize#

cufftResult cufftDeviceGetDatabaseStrSize(
cufftDeviceHandle handle,
size_t *db_str_size,
cufftDeviceFunctionHandle func_handle,
)#

Gets the size of the database string.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • db_str_size[Out] – Pointer to store the database string size.

  • func_handle[In] – (optional) Any cufftDeviceFunctionHandle returned by cufftDeviceGetDeviceFunctions.

Return values:

  • CUFFT_SUCCESS – Database string size was successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle or func_handle.

    • db_str_size pointer is NULL.

cufftDeviceGetDatabaseStr#

cufftResult cufftDeviceGetDatabaseStr(
cufftDeviceHandle handle,
size_t db_str_size,
char *db_str,
cufftDeviceFunctionHandle func_handle = -1,
)#

Retrieves the database string.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • db_str_size[In] – Size of the buffer to store the database string. Value returned by cufftDeviceGetDatabaseStrSize.

  • db_str[Out] – Buffer to store the database string with size db_str_size.

  • func_handle[In] – (optional) Any cufftDeviceFunctionHandle returned by cufftDeviceGetDeviceFunctions.

Return values:

  • CUFFT_SUCCESS – Database string was successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle or func_handle.

    • db_str pointer is NULL.

    • db_str_size is not equal to the size of the database string returned by cufftDeviceGetDatabaseStrSize.

cufftResult cufftDeviceGetLTOIRSizes(

Gets the sizes of LTOIRs.

cufftDeviceCodeType#

There are two types of codes that can be returned by cufftDeviceGetNumLTOIRs:

  • LTOIRs and

  • fatbinary containing LTOIRs.

typedef enum cufftDeviceCodeContainer_t {
   CUFFT_DEVICE_LTOIR = 0,
   CUFFT_DEVICE_FATBIN = 1
} cufftDeviceCodeContainer;

cufftDeviceGetLTOIRs#

cufftResult cufftDeviceGetLTOIRs(
cufftDeviceHandle handle,
size_t code_count,
char **code_ptrs,
cufftDeviceCodeContainer *code_containers,
cufftDeviceFunctionHandle func_handle = -1,
)#

Retrieves the LTOIRs.

Parameters:

  • handle[In] – cufftDeviceHandle returned by cufftDeviceCreate.

  • code_count[In] – Number of LTOIRs to retrieve. Value returned by cufftDeviceGetNumLTOIRs.

  • code_ptrs[Out] – Pointer to an array of array of char to store the LTOIRs.

  • code_containers[Out] – Pointer to an array of cufftDeviceCodeContainer with length code_count to store the code types.

  • func_handle[In] – (optional) Any cufftDeviceFunctionHandle returned by cufftDeviceGetDeviceFunctions.

Return values:

  • CUFFT_SUCCESS – LTOIRs were successfully retrieved.

  • CUFFT_INVALID_VALUE –

    • Invalid handle or func_handle.

    • code_ptrs pointer or code_containers pointer is NULL.

    • code_count is not equal to the number of LTOIRs returned by cufftDeviceGetNumLTOIRs.

Note

When writing the data to disk, it is important to write to files with the right file extensions, .ltoir for LTOIRs (CUFFT_DEVICE_LTOIR) and .fatbin for fatbinaries (CUFFT_DEVICE_FATBIN). Otherwise, NVCC will fail to recognize the files.
